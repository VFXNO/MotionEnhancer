# Optional temporal UI training

**Opt-in training and separate experimental runtime export.** On the Train page, select:

- **Off:** unchanged `mefi.train` flow-only behavior, old checkpoints and export.
- **Flow + UI:** `mefi.train_ui --mode joint`; leave Initial weights and its
  SHA256 empty to create **both flow and UI weights from scratch**. Optional
  original flow weights require their exact SHA256 and a new run folder. The
  GUI calculates that SHA256 automatically when you browse to or paste a file.
- **UI only:** `--mode frozen`; requires a checksum-pinned original flow
  checkpoint. Its size/refiner architecture is restored from that checkpoint;
  only the new UI projection/head trains.

### Automatic checkpoint fingerprint in the GUI

Choose a `.pt` file under **Initial weights**. Its **SHA256** field is filled
automatically by a separate, read-only CPU process, so large files do not block
the window. No checkpoint is deserialized, downloaded, changed, or trained by
this calculation. Clearing Initial weights clears the hash for a scratch run.

Wait for the fingerprint to appear before pressing **START TRAINING**. Pressing
Start while hashing only reports that it is still calculating; completion does
**not** automatically start a training job. The trainer still independently
verifies the exact hash before and after loading the initial weights.

An existing saved fingerprint is checked, not silently replaced. If the file
changed, select the original file, or deliberately use **Recalculate** / browse
to the file again to accept its current bytes. A hash identifies bytes; it does
not prove that weights are authentic, safe, compatible, or suitable for a run.
**Continue** restores its saved run and does not require re-reading the original
initial-weight file. The CLI still requires explicit `--init-sha256` whenever
`--init-from` is used; its integrity checks are unchanged.

No training was launched during implementation. Actual runs still need approved
source sequences, dense labels and an agreed budget. The default displayed
2,000-step/30-minute caps are safeguards, not permission to run or evidence that
they are enough for full flow training from scratch. No packages/teachers needed.

## What stays unchanged

Flow + UI calls the original `mefi.train.losses` on the original interpolation
triplets, including all existing flow/refinement/blend targets and loss terms.
Flow augmentation, sampling and validation use the existing data/train code.
The causal UI window is **separate**, not a replacement middle-frame target.
UI features are detached in both modes. The flow and UI parameter groups are
clipped separately so UI gradients do not change the original flow clipping
scale. UI training evaluates two additional overlapping pairs; it is not free.

The existing working icon detector, its thresholds/continuity and flow-only
workflow remain unchanged. Runtime UI is a separate, default-off option;
exporting it does not replace the installed flow-only model.
The UI head is unvalidated and uses dense supervision on detached pair features.
No OCR model or flow teacher is invoked by training. Machine-generated UI
training labels are now a separate explicit opt-in, prepared by Label UI rather
than generated by the optimizer. The 4 ms gaming-load latency target remains unverified.

## Required dense label manifest

**You do not need to write this JSON by hand.** The **Label UI** page can
prepare explicitly selected frame windows, provide manual brushes and optional
local AI suggestions, and generate the PNGs, splits, hashes and manifest for
reviewed samples. See [the step-by-step labeling guide](UI_LABELING.md). AI
suggestions require correction/review and are not automatically accepted truth.

Supply a reviewed **`me-ui-labels-1` JSON** generated by Label UI or another
preparation tool, using approved source recordings. The training loader itself
does not create data or labels and is not the existing flow dataset builder.
The manifest is an exact allow-list, not a folder scan.

### Optional machine-generated training labels

The Label UI page pre-paints each frame and saves only what you review, as
`me-ui-labels-1`. Machine-generated `me-ui-labels-2` manifests from the older
labeling tool are still accepted for training with `--allow-auto-ui-labels`.
Keep small, varied, manually checked validation data with background as well
as UI. Unknown/ambiguous pixels are still ignored, not treated as scenery.

- Default export remains reviewed-only `me-ui-labels-1`, compatible with old runs.
- Explicitly including eligible automatic **training** samples produces
  **`me-ui-labels-2`**. Every sample includes `label_origin` (`human-reviewed` or
  `machine-generated`) and an explicit boolean `reviewed`. Machine samples keep
  `reviewed: false` plus `auto_label` method, template hashes/revision/source,
  parameters, mask statistics and eligibility. They are never represented as
  hand-reviewed labels. Validation/test entries must remain human-reviewed;
  validation/test recordings cannot be automatic teachers either.
- A new run must explicitly enable **Allow machine-generated UI training labels**
  or pass **`--allow-auto-ui-labels`**. Without it, the mixed manifest fails before
  writing a run. Human-only formats cannot carry machine metadata or be a
  disguised downgrade of a mixed manifest. Template source IDs also participate
  in flow/UI source-disjointness checks.
- The saved permission and exact manifest identity are part of the experiment.
  Continue restores them; changing label trust, data or label revisions needs a
  new run. Old human-only continuation defaults to permission off.
- Ordinary human crop sampling is unchanged. For sparse machine supervision,
  a deterministic even-aligned crop fallback includes a fully known positive
  head cell if the usual random crop would contain no known UI. It does not
  invent labels, resize frames, load test data, or change flow cropping.

The following JSON illustrates the original human-only format; mixed exports
are generated by the GUI, not a request to change existing datasets by hand.

```json
{
  "format": "me-ui-labels-1",
  "label_version": "reviewed-coverage-v1",
  "samples": [
    {
      "id": "recording-a-frame-102",
      "source": "original-recording-a-id",
      "split": "train",
      "height": 480,
      "width": 832,
      "frame_ids": [100, 101, 102],
      "frames": [
        {"path": "recording-a/100.png", "sha256": "<64 lowercase hex characters>"},
        {"path": "recording-a/101.png", "sha256": "<64 lowercase hex characters>"},
        {"path": "recording-a/102.png", "sha256": "<64 lowercase hex characters>"}
      ],
      "coverage": {"path": "labels/a-102-coverage.png", "sha256": "<64 lowercase hex characters>"},
      "valid": {"path": "labels/a-102-valid.png", "sha256": "<64 lowercase hex characters>"}
    }
  ]
}
```

The example is a **schema illustration, not a usable dataset**. Replace every
hash, supply actual approved files and add an explicit nonempty `val` split from
different original recordings. Optional `test` entries stay locked and are not
read by this trainer, including during hash verification.

- Paths must be relative and remain inside the manifest directory after path/
  symlink resolution. Only named train/val files are hashed/read, with hashes
  checked again at decoding. No scans, downloads, uploads or implicit discovery.
- Three actual chronological consecutive RGB frames (8-bit, three channels),
  all the declared dimensions. IDs must be adjacent and ascending; a manifest
  cannot itself prove capture chronology, so provenance must be reviewed.
- Width/height are multiples of 16, at least 64. Input resolution is already in
  network coordinates. A training crop must fit: there is **no automatic image/
  label resizing**, flipping, time reversal, synthetic overlay or Arabic mirror.
  Every frame and label uses the same even-aligned deterministic crop.
- `coverage`: lossless **8-bit single-channel PNG** for UI candidate presence in
  the **third/current frame**, 0–255 antialiased coverage. Boxes are not dense
  glyph labels. Do not use opacity, icon/native masks or flow outputs as truth.
- `valid`: separate lossless single-channel PNG, exactly 0=unknown or 255=known.
  Unknown pixels are ignored. At the half-resolution head, a 2×2 cell is ignored
  if any source pixel is unknown; other cells use averaged coverage. A selected
  crop with no fully known cells fails instead of silently training background.
- Split by original recording/game before deriving crops/windows. A `source`
  must identify the original recording and stay identical for renamed copies,
  crops and derived assets. One source cannot cross train/val/test; duplicate
  frame hashes across splits are rejected. These checks cannot detect every
  renamed/re-encoded related recording; provenance still needs review.
- For **joint** training, UI recordings must be disjoint from **all** flow
  recordings/hold-outs. Source-aware complete flow indices are required; missing
  images/legacy source names are rejected, not rebuilt/relabeled. Use the same
  raw original source ID as flow `index.json` (its `source` field, without the
  internal `source:` prefix) wherever a recording is shared, so the guard can
  reject overlap. The original flow splitter is not modified to accommodate UI.
- The Arabic originals in `build-project/Release/captures/20261101-124214` remain
  locked and unused for training/validation. A local path guard also rejects
  those originals in train/val; copying them does not grant training permission.

## Runs, selection and continuation

UI training requires a **new or empty run directory**, separate from every old
flow run, research snapshot or existing dataset/checkpoint directory. It writes:

- `last_ui.pt`: full flow+head weights, optimizer groups, scheduler, AMP scaler,
  RNG, exact next batch/validation position, source identities and job counters.
- `best_ui.pt`: full flow+head weights selected by **lowest UI validation loss**,
  not by interpolation PSNR or a runtime protection score.
- `ui_config.json` and `ui_validation.json`: settings, latest validation loss,
  known-pixel counts and per-source candidate precision/recall/IoU. Validation
  metrics use fixed 0.5 probability/coverage thresholds, not icon/native settings.
  Joint mode separately reports original interpolation PSNR; it does not replace
  UI labels or select a deployable model. Held-out test entries are never scored.

Stop completes the current operation and keeps a resumable checkpoint. Continue
detects `last_ui.pt` even when the UI mode selector is Off, and restores the
saved mode/settings. It never converts an old `last.pt` or research snapshot.
Changed labels, sample/split identity, batch layout or head architecture are
refused without changing old files. A pending interrupted epoch validation is
not silently skipped. Deterministic independent UI sampling resumes without
decoding already-consumed UI windows; bitwise GPU reproducibility is unproven.

Caps are **cumulative completed steps and cumulative wall-clock job minutes**,
including data/validation work. Stop checks occur between operations/samples;
an in-flight GPU operation, decoding or checkpoint write may finish after the
cap. No automatic continuation, cap extension or nonfinite retry. The GUI keeps
saved caps on Continue. CLI cap changes must be explicit; fixed experiment
settings/total epochs cannot change on UI resume (use a new run for those).
Accounting resumes from the latest saved checkpoint; an abrupt termination can
lose unsaved steps/time. These are job stop safeguards, not a hard real-time
deadline or permission to repeat work beyond an approved budget.

UI checkpoints remain `mefi-ui-training-1` / `pair-ui-training-v1` with
`deployable: false`: they are not directly loadable ONNX models. The Export page
now detects them and explicitly converts the saved weights to the separate
`mefi-pyramid-ui-1` runtime contract. No training or source-data decoding happens
during export. The original flow-only checkpoint loader still rejects UI files
rather than silently dropping their head.

## Export and run the trained UI model

1. Restart an already-open AI Trainer after updating its source.
2. On **Export**, browse to the finished run's **best_ui.pt** (UI-validation
   selection), or **last_ui.pt** (most recent saved weights).
3. Choose the network resolution and export. The default UI filename is
   **models/ai_flow_ui.onnx**, not `ai_flow.onnx`. A request to write a UI bundle
   to the canonical flow filename is redirected to `ai_flow_ui.onnx`.
4. Keep its JSON alongside it. Refined backbones also require
   **ai_flow_ui.dis.onnx** and **ai_flow_ui.dis.json**, matching the same bundle ID.
5. Restart the updated Motion Enhancer executable. Select **AI pyramid**,
   keep **Keep static UI sharp** enabled, and check **Trained temporal UI (exp.)**.
   If the option is disabled after exporting, click **AI Model → Refresh**.
   **AI flow refinement** chooses the integrated graph or its DIS companion
   independently of the learned blending-mask option. Stop capture to change.

The GUI copy option installs UI bundles under `ai_flow_ui.*` in other builds;
it does not replace `ai_flow.*`. C++ rebuilds do not stage UI weights implicitly.
`build-project` remains the active application deployment destination.

From `tools/ai-train`:

```powershell
python -m mefi.export runs\ui\best_ui.pt `
  --out ..\..\build-project\Release\models\ai_flow_ui.onnx --width 832 --height 480
```

CLI runtime: `motion_enhancer.exe --capture-window "Window title" --flow-engine ai --ai-temporal-ui`.
`MOTION_ENHANCER_AI_UI_MODEL` can explicitly select another UI ONNX bundle.
This does not use or change `MOTION_ENHANCER_AI_FLOW_MODEL`.

### Runtime safety and limitations

- One shared backbone invocation produces flow, blend preference, candidate
  probability and projected state. There is no second flow encoder for UI.
- FP32 external tensors: `frames [1,6,H,W]`, `previous_state [1,C,H/2,W/2]`,
  `history_valid [1,1,1,1]`; outputs `flow [1,4,H,W]`, `mask [1,1,H,W]`,
  `ui_allow [1,1,H,W]` and `next_state [1,C,H/2,W/2]`. The head is computed at
  half resolution and bilinearly expanded for aligned D3D12 copies. Internal
  learned computation is FP16. The research graph's half-resolution output
  contract has not changed.
- State ping-pong stays on the serialized flow queue. Startup, nonoverlapping
  pairs, skipped IDs, replacement/replayed pairs, capture restart and resize
  invalidate history; the capture pipeline skips cuts, breaking overlap for
  the next pair. A model/variant change requires capture restart.
- Invalid/nonfinite history produces zero candidates. A missing/incompatible
  explicitly selected UI bundle fails capture startup rather than silently
  falling back to DIS or claiming UI detection.
- A finite probability of at least 0.5 admits a pixel to the **existing native
  static/damage/evidence test**. If icon regions are also enabled, admission
  is their union. Neither source directly writes a protected mask or zeros flow.
  Failed/expired candidates also clear previous native evidence outside admission.
- Completion/export is **not** evidence of useful UI detection. Check the
  checkpoint's validation recall/IoU and representative gaming-load timing.
  No accuracy guarantee or 4 ms combined-AI guarantee is established.

### Explicit CLI examples (do not run without data/budget approval)

From `tools/ai-train`, with a fresh run directory:

```powershell
# Both branches from scratch; requires a separately approved full-flow budget.
python -m mefi.train_ui --mode joint --data <flow-dataset> --labels <labels.json> `
  --run <new-ui-run> --preset medium --refiner --epochs <approved-target> `
  --max-steps <approved-step-cap> --max-minutes <approved-job-minutes>

# Only the UI projection/head learns; original checkpoint is read-only.
python -m mefi.train_ui --mode frozen --init-from <flow-best.pt> `
  --init-sha256 <exact-checkpoint-sha256> --labels <labels.json> --run <new-ui-run> `
  --max-steps <approved-step-cap> --max-minutes <approved-job-minutes>

# No implicit change of data, settings, schedule or caps:
python -m mefi.train_ui --run <same-ui-run> --resume
```

## Implementation checks, without learning

`test_ui_training.py` uses generated temporary fixtures only. Objective/gradient
checks never call an optimizer step; GUI launches are mocked. Loop/resume tests
replace the objective and validation, mock AMP step dispatch, independently
forbid `AdamW.step`, and assert every saved weight is unchanged. They test
orchestration, not real learning, AMP/GPU continuation, HUD accuracy or latency.
The existing isolated prototype tests still exercise tap parity/history safety.

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:TEMP = "$env:LOCALAPPDATA\Temp\opencode"
$env:TMP = $env:TEMP
```
